§ 01

Overview

A factory operations dashboard for tracking inventory, orders, demand forecasts, and spending across multiple warehouses — built as a self-contained demo with no external dependencies beyond the language runtimes.

The architecture is deliberately thin. A single-page Vue 3 client renders seven views; a FastAPI service exposes a dozen-or-so JSON endpoints; all data is loaded at startup from JSON files in server/data/ and filtered in-memory. There is no database, no auth layer, no message bus. State changes do not persist across server restarts.

§ 04

Data Flow — Dashboard Load

Tracing a single user interaction from cold start to rendered KPI card.

01

Browser requests the SPA

User navigates to http://localhost:3000/. Vite serves index.html and the Vue bundle. Vue Router matches the root path to Dashboard.vue.

02

Component mounts & fires API call

Inside Dashboard.vue's setup hook, the component invokes api.getDashboardSummary({ warehouse, category, status, month }) from client/src/api.js. Axios builds URLSearchParams from the current filter state.

03

HTTP traverses to the API

GET http://localhost:8001/api/dashboard/summary?warehouse=all&category=all — CORS preflight passes (allow-all in dev), the request lands on the FastAPI route.

04

FastAPI applies in-memory filters

The handler reads inventory and orders from module-level lists (loaded once at startup via mock_data.py). A shared apply_filters() helper sequentially narrows the lists by warehouse, category, status, and month/quarter.

05

Aggregates & Pydantic validation

The route computes summary metrics — total_inventory_value, low_stock_items, pending_orders, total_backlog_items, total_orders_value — and returns a typed response. Pydantic v2 serializes the shape and emits JSON.

06

Vue renders the KPI grid

Axios resolves; the component stores the response in a reactive ref. Computed properties derive currency-formatted strings, fulfillment percentages, and revenue-vs-goal progress. The template renders KPI cards and SVG charts.
